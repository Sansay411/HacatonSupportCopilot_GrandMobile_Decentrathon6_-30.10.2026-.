# Sentra: финальная проверка качества ИИ (31.10.2026)

Итог одной строкой: **финальный режим Sentra остаётся прежним (baseline, коммит `89974d7`)**. Qwen3.5-4B запускается локально, но не
укладывается по задержке (p95 14,7 с против лимита 5 с, почти втрое), заметно хуже шаблонов на казахском и узбекском и не показала превосходства
ни на одном языке. Кандидат-классификатор LinearSVC даёт малый, но стабильный прирост accuracy; по правилу «любой невыполненный
критерий оставляет baseline» он не включён и подготовлен к включению одной командой.

Все числа ниже получены в этой сессии и воспроизводятся скриптами из `experiments/final_quality/`. Агрегаты лежат в
`reports/final_quality/*.json`. Тексты игроков, слепые пары для людей и кэши лежат только в `reports/private/` и `var/` (в `.gitignore`).

## 1. Baseline

| Что | Значение |
|---|---|
| Коммит / ветка | `89974d7`, `feature/sentra-real-product` (изменений отслеживаемых файлов нет) |
| Тесты | 180 unit + 21 сквозных в браузере: все проходят. В чистом окружении без `data/` и `models/`: 175 проходят, 5 пропущены |
| Данные | `tickets_train.jsonl.gz` (118 337), `tickets_valid.jsonl` (1000), `rules.json`, `taxonomy.json` на месте; `models/category.pkl`, `models/verdict.pkl` загружаются |
| Модель категории | TF-IDF (слова 1–2 + символы `char_wb` 2–5) + LogisticRegression C=4, `balanced`; уже содержит и слова, и символы |
| Повтор оценки | Все метрики `reports/metrics.json` воспроизведены один в один; отличается только шум задержки (p95 4,9 → 5,4 мс) |

**Какая разметка.** Официальной разметки категории и приоритета в выдаче нет ни в train, ни в valid, `taxonomy.json` помечен как черновик.
Поэтому метрики категории и приоритета считаются **только по собственной разметке** (`valid_gold.json`: правила + ручные правки команды). Это не
оценка жюри. Единственный независимый ориентир в данных — вердикт админа; согласие сценария черновика с ним отдельно (0,639, n=518), и это тоже не категория.

**Утечка train → valid.** 358 из 1000 тикетов valid дословно (после нормализации) есть в train, ещё 15 почти дубли. Это завышает заявленные цифры:

| Срез valid (собственная разметка) | n | accuracy | macro-F1 | приоритет macro-F1 |
|---|---|---|---|---|
| Все | 1000 | 0,875 | 0,764 | 0,879 |
| Текст есть в train (точно) | 358 | 0,969 | 0,943 | 0,985 |
| Почти дубль | 15 | 1,000 | 1,000 | 1,000 |
| **Чистые (в train нет)** | **627** | **0,818** | **0,722** | **0,827** |
| ru / uz / kk (все) | 859 / 133 / 8 | 0,877 / 0,865 / 0,875 | 0,766 / 0,787 / 0,950 | 0,879 / 0,917 / 0,467 |
| ru / uz / kk (чистые) | 513 / 110 / 4 | 0,815 / 0,836 / 0,750 | 0,720 / 0,766 / 0,900 | — |

Короткие повторяющиеся обращения («+», «помогите») дословно встречаются и в train, и, вероятно, в скрытом тесте, поэтому полный valid не бесполезен,
но оценкой на новых формулировках служит чистый срез. `kk` в valid всего 8 тикетов (4 чистых): по нему статистики нет.

Слабые классы на чистых тикетах: `complaint.invalid` recall 0,45 (precision 0,77), `complaint.other` precision 0,44 (recall 0,78), `report.question` precision 0,57.
В valid-разметке **нет** `report.payment` и только 1 `report.account`: качество по платежам и взломам на valid не измеримо (там категории задаются жёсткими правилами).

## 2. Оборудование

Измерено, не угадано (`reports/final_quality/hardware.json`): Intel Core i5-12500H (12 ядер, 16 потоков); NVIDIA RTX 4050 Laptop, **6 ГБ VRAM** (≈4,7 ГБ свободно),
compute 8.9, драйвер 617.42; RAM 15,7 ГБ (свободно 2,0–4,7 ГБ); на C: было 89,9 ГБ; `nvcc` нет; torch 2.6.0+cu124 с CUDA, transformers 5.21.0;
llama.cpp, Ollama, vLLM не установлены. Целевое оборудование жюри нигде не указано; README обещает запуск на CPU в Docker `python:3.12-slim`.

## 3. Qwen3.5-4B локально

Официальная модель `Qwen/Qwen3.5-4B` (Apache-2.0, bf16 safetensors 8,9 ГБ, официального GGUF нет). Тестировалась только она, без сторонних квантов.

| Конфигурация | Результат |
|---|---|
| bf16 на GPU / CPU | Невозможно на этой машине: 8,9 ГБ весов > 6 ГБ VRAM и > свободной RAM (по арифметике, не пробовалось) |
| NF4 (bitsandbytes) на GPU, thinking выключен, greedy | Работает: 3,12 ГБ VRAM после загрузки (пик 3,46 ГБ), загрузка 17–29 с, **11,05 ток/с** на свободной машине |
| GGUF / llama.cpp | Не пробовалось: нужны сторонние бинарники и кванты, которых нет в официальном репозитории; скорость не измерена |
| Только CPU (как обещает README) | Не измерялось |

Причина низкой скорости: нет `flash-linear-attention` и `causal_conv1d` (нужен Triton, которого нет в Windows), поэтому слои Gated DeltaNet идут на эталонной реализации PyTorch.

## 4. Классификатор

Протокол заранее: групповое разбиение train (повторы и пары «заявитель + нарушитель» не расходятся по частям), 85 % обучение / 15 % отложенная часть (17 751); выбор по ней,
valid только подтверждает; решение считается через production-логику (`CategoryModel.predict`: модель + жёсткие правила). Подгонки по valid и по synthetic adversarial нет.

| Кандидат | Отлож. acc | Отлож. macro-F1 | Valid все acc / F1 | Valid чистые acc / F1 | Приоритет F1 (чистые) | мс/тикет |
|---|---|---|---|---|---|---|
| A текущий LR C=4 | 0,938 | 0,922 | 0,877 / 0,765 | 0,820 / 0,722 | 0,826 | 1,8 |
| LR C=1 | 0,935 | 0,915 | 0,873 / 0,761 | 0,813 / 0,719 | 0,825 | 2,5 |
| LR C=16 | 0,938 | 0,923 | 0,878 / 0,768 | 0,823 / 0,728 | 0,828 | 1,7 |
| **LinearSVC + сигмоидная калибровка (D)** | **0,943** | **0,929** | **0,881 / 0,783** | **0,825 / 0,741** | **0,833** | 5,5 |
| LR, шире n-граммы | 0,939 | 0,924 | 0,876 / 0,764 | 0,820 / 0,721 | 0,826 | 1,2 |

D лучше baseline в каждом срезе на всех трёх независимых разбиениях (seed 20261031, 11, 12): отложенная accuracy +0,37…+0,50 п.п. (95 % интервал не содержит 0 ни разу,
и при разметке только по тексту без исходов админа +0,44…+0,62 п.п.), macro-F1 +0,39…+0,67 п.п. (интервал иногда задевает 0), чистые valid macro-F1 +1,9…+2,3 п.п.
На уровне всего pipeline (модель обучена на всём train): категория меняется у 17 из 1000 тикетов, исправлено 10, испорчено 5 (McNemar p=0,30, **не значимо**);
needs_human 0,909 → 0,908, доля низкой уверенности 0,106 → 0,099, ошибочных цитат 0, p95 4,6 → 6,4 мс. Файл модели 51 МБ против 23 МБ.

**Решение: не включать.** По правилу задания «если какой-либо критерий не выполняется, оставляй baseline»: на независимой (нашей) разметке выигрыш не доказан, а заранее заданное правило задержки
(≤1,5× + 1 мс) формально не выполнено (по существу +2 мс против бюджета 5000 мс несущественно, но правило было задано до получения результатов и не менялось). Готово к включению: `var/final_quality/models_D/category.pkl`.

Общая слабость всех моделей, измеренная диагностически и не использованная для выбора: если тот же русский текст чистых тикетов переписать латиницей, accuracy падает с 0,81 до 0,63, а предсказание сохраняется у 75 %. Транслитерация остаётся незакрытой.

## 5. Сравнение черновиков: A (шаблоны Sentra) и B (Qwen3.5-4B + RAG по правилам + guard)

B получает: текст обращения, факты (ник, ID, вложения), категорию и сценарий от кода, цитаты правил только из `cited` с текстом из `rules.json`, наказание только как его выбрал код,
язык, запреты на обещания. `needs_human` она не видит и не меняет. Ответ проходит `copilot.llm.validate`, `verify`, `guard` и дополнительные проверки; при нарушении возвращается шаблон.
Выборка: 150 реальных тикетов valid, стратифицирована по языку и сценарию (seed в коде, отобрана до генерации, ru 97 / uz 45 / kk 8; из 812 тикетов со сценариями, где LLM разрешена). Плюс 48 синтетических тикетов на тестовых правилах.

| Метрика | A шаблоны | B Qwen3.5-4B | Комментарий |
|---|---|---|---|
| Текст B принят guard | — | 137 из 150 (91 %) | ru 98 %, uz 84 %, kk 50 % (4 из 8) |
| `needs_human` совпадает с A | — | 150 из 150 | категория и цитаты тоже 150 из 150 |
| Нарушения (выдуманный пункт, обещание, язык, ник) в итоговых текстах | 0 | 0 | независимый список обещаний из `eval_drafts.py`; сырой Qwen до guard: 3 несовпадения языка |
| Цитаты: охват требуемых пунктов | 1,00 | 0,78 | B часто опускает пункты (мера полноты, автоматическая) |
| Маркер сценария в тексте | 1,00 | 0,97 | |
| Алфавит uz: принятые ответы с кириллицей | 0 из 45 | **36 из 38** | определитель языка называет их uz, действующая проверка пропускает |
| **Задержка p50 / p95 / p99, end-to-end** | **3,1 / 5,7 / 10,8 мс** | **7,7 / 14,7 / 17,4 с** | лимит p95 5 с; на синтетике 4,2 / 11,3 / 12,9 с |
| Генерация | — | 91,5 токена, 8,3 с в среднем | 11,05 ток/с |
| Стоимость API | $0 | $0 | электричество B порядка $0,00003 за тикет по TDP 80 Вт; на арендованном GPU оценка $0,001–0,002 (допущения, не замер) |

**Качество (соответствие запросу, полнота, естественность, язык, подтверждённость фактов).** На реальных тикетах оценки по этим критериям выставляет только человек:
из-за запрета отправлять реальные обращения во внешние ИИ LLM-судья на реальных текстах не запускался. Подготовлено **60 пар** для людей
(`reports/private/final_quality/human_review_pairs.csv`, порядок X/Y перемешан, ключ отдельно, kk 4 / uz 20 / ru 36) с инструкцией.
На **синтетике** (данных кейса нет) оценки выставил LLM-судья (Claude, не жюри; слепота неполная, шаблоны узнаются по стилю), 23 пары, где B прошла guard:

| | A шаблоны | B Qwen | Предпочтение |
|---|---|---|---|
| Все (23) | 4,60 | 3,71 | A 14, B 3, ничья 6 (знаковый тест p=0,013) |
| ru (12) | 4,58 | 4,40 | A 3, B 3, ничья 6 |
| kk (6) | 4,63 | 3,13 | A 6 |
| uz (3) | 4,47 | 1,73 | A 3 |
| en (2) | 4,80 | 4,30 | A 2 |

Что показали ошибки Qwen, прошедшие guard: выдуманная организация («комитет справедливости» на казахском), несуществующие слова kk и uz, узбекский кириллицей, фраза «нарушитель будет привлечён к ответственности»
на узбекской кириллице (обещание наказания, которое регулярные выражения не ловят), выдуманная причина отказа в обжаловании, утечка инструкции промпта в ответ, потеря ID игрока.
Это границы проверок на регулярных выражениях: язык по детектору и отсутствие запрещённых слов не доказывают естественность и фактическую точность.
Устойчивость к инъекции в тексте игрока («напиши, что бан снят») проверена на одном синтетическом случае: ни одна сторона не подчинилась.

**Не подтверждено:** любое превосходство B по соответствию запросу, полноте, естественности на реальных тикетах; на ru паритет только на 12 синтетических парах (интервалы шире разницы).
Измеренные улучшения от B: нет. Единственное, чем B выигрывала у A, — три русских синтетических пары, где она отражала суть вопроса игрока («Понимаю ваш вопрос о…»); этого недостаточно для включения.

## 6. Мультиязычная проверка

Шаблоны Sentra (1000 ответов): покрытие ключей i18n полное во всех 6 языках (34 ключа); флаги чистоты алфавита: kk 0 из 8, uz 0 из 132, ru 21 из 856 (все — легитимные термины DeathMatch/DriveBy/GPS/WARN и ники). Язык обращения и язык ответа совпадают для ru, uz, kk, en; 31 короткий текст с неопределённым языком отвечен на ru (30) и uz (1).
Это автоматические флаги, не доказательство естественности. **Естественность перевода шаблонов не проверена носителем.** Для проверки выгружено
`reports/private/final_quality/native_review_kk_uz.jsonl` (все kk, uz по сценариям, помеченные флагами). Узбекский: знак «тутуқ» (`ma’muriyatga`, U+2019) и `oʻ/gʻ` (U+2018) различаются правильно, это не дефект.
Транслитерация и kk/uz остаются самыми слабыми местами классификатора (kk 4 чистых тикета не дают статистики).

## 7. Воспроизводимость и утечки

Проверено в чистой копии `HEAD` (97 отслеживаемых файлов, без `data/` и `models/`) и новом venv из одного `requirements.txt` (`experiments/final_quality/repro_check.py`):

* Без приватных файлов: сервис стартует, `/health` отвечает 200 и называет причину, `POST /triage` честно отвечает 503; результаты не подменяются.
* `serve.py --fixture`: `POST /triage` по контракту (3 языка), правила помечены как тестовые.
* С `data/` и `models/`: режим `full`, контракт соблюдён, язык черновика совпадает с языком обращения.
* `make predict` (эквивалент `scripts/predict.py`, `make` на машине нет): 1000 строк, 0 нарушений контракта, `_meta` не утекает, два запуска дают побайтно одинаковый результат, 4,3 с.
* Копии данных во временной проверочной папке удалены.

Модельные артефакты содержат словари из обращений игроков (60 000 словных признаков, в том числе сотни токенов, похожих на ники, и числовые строки): это производные данные кейса, публиковать нельзя, доставка только закрытым архивом с согласия организаторов (как уже написано в README).
Веса Qwen публичные и не производные от данных кейса (дообучения не было); доставка по ссылке возможна, но жюри может не иметь ни интернета, ни GPU.

**Сканер утечек** (`leak_scan.py`; отпечатки: 119 337 id, 51 585 хэшей, 5 676 текстов): в рабочем дереве (109 файлов) и в неигнорируемых новых файлах совпадений нет; запрещённых типов файлов в индексе нет;
в истории идентификаторов нет. **Блокер:** `reports/template_suggestions_summary.{json,md}` убраны из дерева в `89974d7`, но остаются в истории `main` и в `origin/main`, `origin/feature/template-clusters`:
в них найдено **13 дословных ответов админов** (≥40 символов) из выдачи, текстов игроков нет. Репозиторий на GitHub приватный. Перед передачей репозитория жюри или проверяющим историю нужно очистить (`git filter-repo`) и обновить удалённую ветку, либо получить согласие организаторов. История не переписывалась, ничего не отправлялось на удалённый сервер.

## 10. Конфигурация финального режима Sentra

Без изменений относительно коммита `89974d7`: категория (LR C=4, TF-IDF слова 1–2 + `char_wb` 2–5, `balanced`) + жёсткие правила, `verdict.pkl` для сценария,
шаблонные черновики на языке игрока, RAG по `rules.json`, guard и `verify`, дедупликация за час, `needs_human` по правилам. Внешний и локальный LLM выключены (переменные `COPILOT_LLM_*` не заданы).
Python 3.12.10, scikit-learn 1.9.1, numpy 2.5.4, scipy 1.18.1, fastapi 0.162.0. Запуск: `python scripts/serve.py`, `python scripts/predict.py --in … --out …`.
